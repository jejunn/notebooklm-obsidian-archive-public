# 사용 안내

이 문서의 과목·질문·식별자는 예시입니다. 개인 질문 원문이나 강의자료는 포함하지 않습니다.

## 전제로 하는 학습 흐름

1. 한 강의를 공부하며 NotebookLM에 질문합니다.
2. 새 페이지를 다룰 때 `2강 23페이지 설명해줘`처럼 번호를 명시합니다.
3. 같은 페이지 후속 질문에는 번호를 생략할 수 있습니다.
4. 공부가 끝나면 대화를 Obsidian에 처음 저장합니다.
5. 저장 결과를 확인한 뒤 NotebookLM 채팅은 직접 삭제합니다.
6. 복습할 때 새 채팅으로 질문하고, 기존 강의 노트에 복습 추가합니다.

강의 구분과 복습 영역은 이 학습 흐름을 위해 선택한 문서 구조입니다. 다른 공부 방식을 자동으로 판단하거나 변환하지 않습니다. 강의를 섞어서 질문했다면 저장 전에 경고와 미리보기를 확인해야 합니다.

## 질문 서식의 정확한 의미

페이지 번호는 질문 문자열의 `숫자 + 페이지` 표현에서만 읽습니다. 띄어쓰기를 허용합니다. 과목·강의는 저장 창의 선택을 사용하며, 질문 첫머리의 `N강`은 다른 강의 경고에만 사용합니다.

| 입력 | 결과 |
|---|---|
| `23페이지 설명해줘` | 23페이지 새 그룹 |
| `2강 23 페이지 설명해줘` | 23페이지 새 그룹. 선택한 강의와 2강이 다르면 경고 |
| `그 식을 다시 설명해줘` | 앞서 지정한 페이지 상속 |
| `다음 페이지를 설명해줘` | 자동으로 1 증가시키지 않음. 앞선 페이지 상속 |
| `23페이지 설명해줘`를 두 번 질문 | 같은 번호의 그룹 두 개. 질문도 두 번 보존 |
| `23 → 24 → 23페이지` 순서의 질문 | 질문 순서대로 그룹 생성. 기존 23페이지 그룹에 합치지 않음 |
| `23, 24페이지 비교해줘` | 여러 페이지 경고. 마지막 번호 24 사용 |
| `23~25페이지 설명해줘` | 범위 확장 미지원. 끝의 25페이지만 인식될 수 있음 |
| `p.23`, `page 23`, `23쪽` | 해당 표기를 새 페이지로 인식하지 않음 |

새 대화에서 페이지를 명시한 적이 없다면 `페이지 미지정`으로 남습니다. 새 복습 대화가 이전 학습 대화의 마지막 페이지를 상속하지는 않습니다. 같은 복습 대화를 여러 번 저장할 때는 그 대화에서 앞서 명시한 마지막 페이지를 상속합니다.

## 저장 방식과 파일 이름

과목 `예제 과목`, 강의 `2`를 선택하면 `예제 과목/2강.md`에 저장합니다. 과목에는 경로 구분자나 줄바꿈을 넣을 수 없고 강의 번호는 1 이상의 정수입니다.

| 선택과 상태 | 결과 |
|---|---|
| 처음 저장 / 파일 없음 | 조회한 대화 전체로 새 노트 생성 |
| 처음 저장 / 파일 있음 | 중단. 빈 파일도 덮어쓰지 않음 |
| 복습 추가 / 기존 관리 노트 / 새 대화 | 확인 후 대화 전체 추가 |
| 복습 추가 / 이미 저장한 같은 대화 | 마지막 저장 turn 뒤의 신규 Q&A만 추가 |
| 같은 대화 / 신규 Q&A 없음 | 알림 후 파일 유지 |
| 복습 추가 / 파일 없음 | 중단. 먼저 처음 저장 필요 |
| 복습 추가 / 수동 작성 노트 또는 다른 과목·강의 | 중단. 관리 메타데이터 확인 필요 |
| 저장 위치 손상 또는 기준 turn 없음 | 중단. 전체를 새 복습으로 취급하지 않음 |

두 가지 저장 모드는 사용자가 선택합니다. 대화 ID가 다르다는 이유만으로 새 강의나 복습을 자동 판정하지 않습니다.

## 실행과 확인

NotebookLM 노트북 페이지에서 `NotebookLM archive`를 누르고 과목·강의와 저장 모드를 정합니다. **검증만 실행**이 체크되어 있으면 조회·검증·대상 확인까지만 진행하고 Obsidian을 읽거나 쓰지 않습니다. 따라서 이 실행만으로 대상 파일이 존재하는지까지 검증하지는 않습니다.

실제 저장에서는 다음 순서로 진행합니다.

1. 최근 대화 후보를 조회하고 전체 조회인지 확인합니다.
2. 시작 질문·마지막 질문·질문 수와 경고를 보여줍니다.
3. 사용자가 대상 대화를 확인하면 API 키를 입력받습니다.
4. 기존 노트를 읽어 처음 저장·복습 추가 가능 여부를 판단합니다.
5. 저장 대상과 신규 분량을 보여주고 최종 확인을 받습니다.
6. 노트를 다시 읽어 확인 중 편집되지 않았는지 검사하고 저장합니다.

새 질문이 없는 경우에는 최종 쓰기 확인이나 PUT 없이 무변경 종료합니다. 키 입력·최종 확인을 취소하면 저장하지 않습니다. API 키는 파일에 기록하지 않습니다.

**최근 후보 조회는 현재 화면의 과거 대화를 정확히 식별하는 기능이 아닙니다.** 시작·마지막 질문이 다르면 취소하고 대상 대화를 다시 확인합니다. 대화 전체를 확보하지 못하면 저장하지 않으므로, 긴 대화 알림이 나오면 이 버전으로 일부만 저장하려고 반복 실행하지 않습니다.

## 만들어지는 노트

다음은 가상 예시입니다. 실제 문서에는 질문·답변 시각도 포함됩니다.

```markdown
# 2강

## 23페이지
### Q
2강 23페이지 설명해줘.
### A
예제 설명입니다.

### Q
여기서 x는 왜 증가해?
### A
후속 질문에 대한 예제 설명입니다.

---

## 추가 질문
### 2026-10-10
#### 23페이지
##### Q
23페이지 공식을 다시 설명해줘.
##### A
복습 답변입니다.
```

복습은 문서 끝에 추가하고 최초 학습의 페이지 그룹으로 재분류하지 않습니다. 같은 날짜의 복습은 날짜 제목을 다시 만들지 않습니다. 페이지가 같아도 명시적 새 질문은 새 그룹을 열 수 있습니다. 날짜와 시각은 한국 시간 UTC+9 기준입니다.

## 수식·출처·빈 답변

LaTeX 인라인·블록 구분자를 Obsidian용 `$...$`, `$$...$$`로 정리합니다. 코드 안의 구분자는 보존합니다. 수식 내용 자체를 고치거나 표·수식의 모든 렌더링을 보장하지는 않습니다.

답변 문장 끝 등의 연결되지 않은 `[1]`, `[1, 2]` 표기를 보수적으로 제거합니다. 질문의 숫자 괄호, 코드·수식·링크·명시적 범위는 보호합니다. 문맥을 완전히 이해하는 출처 분류기는 아니므로 애매한 표기는 남을 수 있고, 모든 숫자 괄호를 없애지는 않습니다. 출처 파일과 citation 연결은 내보내지 않습니다.

빈 답변도 turn으로 보존하고 빈 답변임을 표시합니다. 답변 없이 끝나는 홀수 turn, 중복 ID, 질문·답변 순서 이상은 저장을 중단하는 구조 오류입니다. 같은 질문 문구라도 ID가 다르면 각각 보존합니다.

## 자주 확인할 부분

| 증상 | 확인 |
|---|---|
| Archive 버튼 없음 | 노트북 페이지인지, Userscripts 활성화·사이트 허용·스크립트 활성화 여부, 확장 팝업과 새로고침 |
| 조회 실패 | NotebookLM 로그인 상태와 질문이 있는 대화. 비공식 RPC 변경 가능성 |
| 저장 실패 | Obsidian 실행, 플러그인 활성화, API 주소·포트·키·인증서 |
| 처음 저장에서 기존 파일 경고 | 같은 노트에 추가하려는 목적이면 복습 추가 선택 |
| 복습에서 메타데이터 오류 | 처음 저장으로 만든 동일 과목·강의 노트인지 확인. 관리 필드를 임의로 지우지 않음 |
| 페이지 미지정 경고 | 질문에 한국어 페이지 번호가 명시되어 있는지 확인 |
| 다른 강의 경고 | 선택한 저장 강의와 질문 내용 확인. 자동 제외·분할되지 않음 |
| 긴 대화 알림 | 400 turn 요청 후 다음 토큰이 남음. 아직 다중 조회 미지원 |

설치 파일을 교체하면 Userscripts 확장 팝업을 한 번 열고 페이지를 새로고침합니다. 로컬 API의 인증서는 [플러그인 공식 안내](https://github.com/coddingtonbear/obsidian-local-rest-api)에 따라 설정합니다. API 키나 인증서 개인키를 GitHub 이슈·채팅·예제 파일에 넣지 않습니다.
