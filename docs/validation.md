## Safari 웹앱 확인

2026-10-10 사용자가 Safari 웹앱에서도 `NotebookLM archive` 버튼이 나타나고 클릭에 반응한다고 보고했습니다. 웹앱에서 스크립트가 실행되고 버튼이 동작하는 것은 확인된 상태입니다. 이 시점에는 대화 조회와 실제 Obsidian 저장까지 이어지는 전체 흐름을 확인하지 않았습니다.

## 2026-10-12 HTTPS 조회 실패와 사용자 확인

- 대화 조회·검증을 통과한 뒤 Obsidian GET에서 `vault read did not complete`가 발생했습니다. 수정 주소 `127.0.0.1`과 과목 파일 경로가 실제 실패 요청에 적용된 것을 확인했습니다.
- Safari 콘솔에서 **이 서버에 대한 인증서가 유효하지 않습니다**를 확인했습니다. 로컬 API 사이트 접근 허용만으로 인증서 신뢰가 해결되지 않았습니다.
- 서버 인증서 SAN은 `127.0.0.1`만 포함했습니다. 공개 CA를 명시한 TLS 검사에서는 `localhost` 이름 불일치로 실패했고 `127.0.0.1`은 HTTP 200이었습니다. 이는 브라우저의 CA 신뢰 설정과 별개입니다.
- 사용자가 CA 인증서의 키체인 등록·SSL 신뢰 절차 이후 **정상 동작**을 보고했습니다. 이 최종 보고에서 Safari와 웹앱 각각의 성공 여부를 따로 답변받거나 PUT 응답·저장 파일을 다시 측정하지는 않았습니다.
- 현재 소스·설치 빌드는 loopback IP를 기본값으로 사용하고 조회 실패 알림에 설정 확인 항목을 표시합니다. 개인 인증서, 키, 원문, 노트와 실제 요청 캡처는 이 저장소에 포함하지 않습니다.

## 아직 직접 확인하지 않은 항목

- 새 복습 대화 전체를 **실제 Obsidian 노트에 쓰는** 최종 실사용 검증. 모의 API에서는 추가 PUT 1회와 반복 실행의 PUT 0회를 확인했습니다.
- HTTPS 설정 변경 이후 Safari와 웹앱 각각의 성공 PUT 응답·결과 파일을 분리하여 재측정한 검증. 정상 동작은 위 사용자 보고로 확인했습니다.
- 다른 브라우저·OS·플러그인 버전, 다른 언어 질문, 다른 시간대.
- 400 turn 이후의 다중 페이지 조회. 현재 기능은 다음 토큰이 있으면 알림·저장 중단입니다.

## 2026-10-13 범위형 출처 제거

- 문장부호 앞·줄 끝·표 셀 끝의 `[1-3]`, `[1-4]`, `[4-6]` 표기와 쉼표 목록에 포함된 하이픈 범위형을 제거합니다.
- 문장 중간과 ‘구간·범위’ 뒤의 보호 규칙은 유지합니다. 남는 두 유형과 재검토 조건은 [사용 안내](usage.md#알려진-제한-출처처럼-보이지만-보존하는-표기)에 기록했습니다.
- 범위형 Markdown 참조 링크와 범위 안에 정의된 참조 번호를 보존하는 테스트를 포함해 공개본 347개 테스트가 통과했습니다.
- 로컬에 설치한 출처 정리 모듈은 검증한 소스와 같은 결과를 내는 것을 확인했습니다. 기존 노트를 수정하거나 Safari에서 새 답변을 실제 저장하는 검증은 수행하지 않았습니다.

## 공개본 변경

동작 알고리즘을 확장하지 않고 예제 과목·가상 식별자를 적용했습니다. 공개용 README, 질문 서식·사용 전제·설계·제한·검증 문서를 새로 작성했습니다. 개인 경로, 원래 노트북·대화·turn 식별자와 실제 노트·요청 기록을 가져오지 않습니다.

원래 소스에 있던 개인 대화의 정확한 페이지 재질문·코드 블록 수 측정 테스트 4개는 비공개 보관본에 남깁니다. 공개본은 해당 원본 기록을 요구하지 않는 합성 테스트로 구성합니다. 실패 테스트를 건너뛰어 성공으로 표시하지 않으며, 합성 데이터로 과거 실측값을 증명한다고 주장하지 않습니다.

## 재현

```sh
bun test
bun run tools/generate-test-fixtures.js
bun run build:userscript
```

Bun 1.4.2를 기준으로 합니다. 테스트는 모의 요청과 가상 파일을 사용하며 실제 NotebookLM 로그인이나 Obsidian 키가 필요하지 않습니다. 예제 데이터 생성기도 개인 파일을 읽지 않습니다. GitHub Actions는 테스트, 예제 재생성, 빌드, 생성 파일 일치를 검사합니다.

2026-10-10 공개 스냅샷의 테스트와 빌드 결과는 `docs/publication-checks.json`에 보존합니다. 이후 변경은 GitHub Actions에서 확인합니다. 이전 비공개 커밋을 복사하지 않고 GitHub의 비공개 이메일 주소로 새 첫 커밋을 작성합니다. 0.1.1 수정은 공개본과 비공개 보관본에 각각 반영했습니다. GitHub 배포 파일의 갱신은 Mac 설치 파일을 자동 교체하지 않습니다.
